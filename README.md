# Materials for "Deep Semiparametric Partial Differential Equation Models"
<a href="https://arxiv.org/pdf/2506.22779">https://arxiv.org/pdf/2506.22779</a>

## Overview

- ### Directory ***simulation*** contains all codes, outputs and plots related to the simulations in *Section 5: Simulation*.
    - The ***code/semipde*** folder is the shared implementation. `config.py` defines the case configuration and the notion of sample size `n` and repetition count `M`; `grids.py` builds the spatial and temporal grids; `operators.py` implements the known differential operators as circular convolution kernels; `networks.py` defines the feedforward networks and the penalty `J`; `data.py` generates the deterministic datasets (including the input `Z`); `model.py` is the profiling model that combines the known operator with the nonparametric mechanism and integrates it with an explicit ODE solver; `train.py` implements Algorithm 1; `inference.py` implements Algorithm 2; `baselines.py` implements Baselines 1–3 plus the spline/Fourier sieve; `cascading.py` implements Baseline 4; `metrics.py` computes estimation errors, coverage and Q–Q statistics; `cases.py` assembles the published cases and is the single source of truth for their settings; `study.py` handles sharding, resume and aggregation; `sieve.py`, `influence.py` and `resample.py` contain supporting routines.
    - The ***code/scripts/exp_study.py*** file is the main driver for every simulation case. `--case` selects `rd` (Fisher–KPP reaction–diffusion), `burg` (forced Burgers with the switched input `Z`), `advz` (advection with the auxiliary variable in the known operator) or `np` (Nernst–Planck), and the positional argument selects `estimate`, `inference`, `ablation` or `calibration`. The file ***code/scripts/exp_example2.py*** is a dedicated driver for the forced-Burgers example. The files ***code/scripts/run_study.sh*** and ***run_example2.sh*** shard a study across CPU workers, write one JSONL per shard, and aggregate the shards into a summary JSON when they finish.
    - The ***results*** folder stores the aggregated simulation results. `estimate.summary.json`, `inference.summary.json`, `calibration.summary.json` and `ablation.summary.json` are the machine-readable aggregates of the four studies. The ***results/baseline_M8*** folder contains the estimation and prediction tables for all four cases with `f != 0` (`rd_g16.table.txt`, `burg_g16.table.txt`, `advz_g16.table.txt`, `np_g8.table.txt`), including SemiPDE and all four baselines. The ***results/zero_f_M8*** folder contains the same tables for the `f = 0` experiment, in which the data are generated by zero mechanism and the estimator still has to estimate `f`. The file ***results/coverage/size_table.tex*** is the LaTeX coverage table with the 80%, 90% and 95% empirical coverage rates.
    - The ***figures*** folder contains the plots used in the main text and the supplement: rate/error curves, Q–Q plots, histograms, confidence-interval plots, and representative case outputs.
    - Main results: SemiPDE is the best method in all 24 cells of the `f != 0` table (4 cases × 2 noise levels × 3 metrics: parameter error, mechanism error and prediction RMSE). At `sigma = 0.1`, for example, the prediction RMSE (`x 1e-2`) is 0.925 / 1.528 / 0.835 / 1.434 on RD / Burgers / Adv.-Z / Nernst–Planck, against 5.478 / 4.230 / 4.622 / 7.291 for the best baseline. In the `f = 0` experiment the correctly specified parametric model is the efficiency benchmark, while SemiPDE still beats the nonparametric and PINN baselines and recovers only a small spurious mechanism. In the inference study the empirical 95% coverage is 0.948–0.972 (0.926 jointly for the two Nernst–Planck coordinates) at 500 repetitions.

- ### Directory ***realdata*** contains all datasets, codes, outputs and plots related to the two real-data experiments in *Section 6: Real Data Applications*.
    - #### The ***invitro_cell*** subdirectory includes materials for the behaviour of in-vitro cell culture assays (PC-3 scratch test).
        - The ***realdata/realdata1*** folder contains the preprocessed curves (`data/traindata.npy`, `data/testdata.npy`) and the raw supplementary files (***1-s2.0-S0022519315005676-mmc2.xlsx*** … ***mmc7.xlsx***) of Jin et al., *J. Theor. Biol.* (2016).
        - The ***semipde*** folder is a self-contained copy of the shared implementation, and the ***scripts*** folder contains the drivers: ***realdata_cell.py*** fits the data with SemiPDE and the four baselines for the linear or porous variant; ***realdata_ci.py*** reads the fitted `state_dict` and computes the 95% Wald interval for the diffusivity; ***realdata_mechanism.py*** evaluates the fitted reaction mechanism `f(u)` and draws the mechanism figure.
        - The ***runs/realdata_cell*** folder stores the fitted results, one JSON per variant (`linear.json`, `porous.json`) with one entry per method, and the proposal's fitted networks (`linear_ours_model.pt`, `porous_ours_model.pt`).
        - The ***figures*** folder contains the fitted-mechanism figure used in the paper.
        - Main results: for linear diffusion the estimated diffusivity is `D = 1427 [1367, 1487]` µm²/h with test MSE `1.624e-8`, against `913.9` and `1.942e-8` for the logistic benchmark; for porous diffusion, `D = 3538 [3381, 3696]` µm²/h with test MSE `1.567e-8`, against `3036` and `1.800e-8`. The fitted mechanism is close to a logistic law: a parabola explains 89% (linear) and 94% (porous) of its variation.
    - #### The ***vhb*** subdirectory includes materials for the multi-rate viscoelasticity of VHB 4905.
        - The experimental data are the six-grip-speed uniaxial tension curves deposited at Zenodo record 17019463; the three-dimensional finite-element model and its calibration data are from DAVIS 1.0.0 (Wiesheier, Moreno-Mateos, Steinmann; Zenodo 17542379). The solver and the experimental data are not redistributed here; the README gives the download and build steps.
        - The ***scripts*** folder contains the complete pipeline: ***audit_vhb.py*** and ***check_force_sources.py*** audit the data and the force convention, ***prepare_author_run.py*** builds a private copy of the authors' run tree, ***setup_fit_tree.py***, ***setup_hybrid_interp.py*** and ***setup_extra_branch.py*** create the two- and three-branch calibration trees, ***fit_vhb.py*** runs the Levenberg–Marquardt calibration for the spline, Zener or neural-network representation, ***collect_eval.py*** and ***per_rate_cost.py*** collect the five-rate curves and costs, and ***plot_comparison.py*** and ***plot_functions.py*** generate the figures.
        - The ***results/nn3*** and ***results/nn2*** folders store the calibrated networks: `final_metrics.json` (force and displacement errors at every rate), `theta.npy` (network weights), `nn_config.json` (architecture, Zener base and node scales), the per-rate `curves_*.npz`, and `interp_neq/` with the identified interpolation values. The ***results/zener3*** and ***results/zener2*** folders store the parametric baselines in the same format, and ***results/released*** stores the uncalibrated released values evaluated under the same protocol.
        - The file ***results/comparison.csv*** is the per-rate force/displacement error table for all models; the ***results/figures*** folder contains the force–strain comparison, the force-error plot and the identified constitutive functions.
        - The folders `results/nn3`, `results/nn2`, `results/zener3` and `results/zener2` are the curated versions of the runs used in the paper. The workflow below writes fresh fits to `results/fit_*` and fresh evaluations to `results/eval_*`.
        - Main results: the three-branch network reaches a five-rate weighted objective of **86.1**, against **241.9** for the three-branch Zener baseline (factor 2.8) and **288.2** for the two-branch baseline (factor 3.3). It is lower than both Zener baselines at all five rates. On the held-out rates the hole-edge displacement is 1.72 / 0.86 mm, against 2.96 / 2.09 mm for the three-branch Zener model.

## Workflows

#### Note: Requires Python 3 and the following libraries: ***numpy***, ***scipy***, ***torch*** and ***matplotlib*** (see `requirements.txt`). The simulation and cell-culture code runs on CPU. On a shared machine, set `OMP_NUM_THREADS`, `MKL_NUM_THREADS`, `OPENBLAS_NUM_THREADS`, `NUMEXPR_NUM_THREADS` and `VECLIB_MAXIMUM_THREADS` to `1` before importing torch.

- ### Simulation for estimation performance of the proposed method compared to the four baselines.
    - Run the sharded driver from the ***simulation*** directory. `--case` selects `rd`, `burg`, `advz` or `np`; the second positional argument selects `estimate`, `inference`, `ablation` or `calibration`.
    ```bash
    bash code/scripts/run_study.sh 8 estimate --case rd --repeats 50 --epochs 200
    bash code/scripts/run_study.sh 8 estimate --case burg --repeats 50 --epochs 200
    ```
    - Each shard appends its finished jobs to `code/runs/<case>/estimate.jsonl`; the driver aggregates them into `estimate.summary.json` when all shards finish. Set `OUT_DIR` to keep several grids of the same study apart. The curated copies of the runs used in the paper are in `results/`.
    - A single shard can be run by hand:
    ```bash
    python -I code/scripts/exp_study.py estimate --case advz \
        --repeats 50 --epochs 200 --shard 0 --shards 1 --out /tmp/advz.jsonl
    ```
    - Baseline 1 is selected with `--methods para` (the parametric model with `f = 0`); Baseline 2 with `--methods nonpara`; Baseline 3 with `--methods pinn`; Baseline 4 with `--methods cascading`. After aggregation the driver prints the comparison table and writes `estimate.summary.json`; the precomputed tables are in `results/baseline_M8/`.

- ### Simulation for inference of parameters in the SemiPDE model.
    ```bash
    bash code/scripts/run_study.sh 8 inference --case rd --repeats 50 --epochs 200
    ```
    - The coverage fractions and interval widths are written to `inference.summary.json`; the coverage table is `results/coverage/size_table.tex`.

- ### Simulation for identifiability and robustness of the SemiPDE model.
    - This is the `f = 0` experiment: the data are generated with zero mechanism, while the estimator still estimates `f`. It uses the same driver with `--true-f zero`. Give it a separate `OUT_DIR` so it does not overwrite the `f != 0` rows:
    ```bash
    OUT_DIR=runs/zero_f_rd bash code/scripts/run_study.sh 8 estimate \
        --case rd --true-f zero --repeats 50 --epochs 200
    ```
    - The resulting tables are stored in `results/zero_f_M8/`.

- ### Real-data experiment 1: the behaviour of in-vitro cell culture assays.
    - The raw data are available at <a href="http://dx.doi.org/10.1016/j.jtbi.2015.10.040">here</a> and the preprocessed curves are included in `realdata/invitro_cell/realdata/realdata1/`.
    - From the ***realdata/invitro_cell*** directory, run
    ```bash
    python -I scripts/realdata_cell.py --variant linear
    python -I scripts/realdata_cell.py --variant porous
    python -I scripts/realdata_ci.py --variant linear
    python -I scripts/realdata_ci.py --variant porous
    python -I scripts/realdata_mechanism.py --out figures/realdata1_nonpart_ours.png
    ```
    - The fits merge into `runs/realdata_cell/linear.json` and `runs/realdata_cell/porous.json`; the proposal's networks are saved next to them.

- ### Real-data experiment 2: multi-rate viscoelasticity of VHB 4905.
    - The experimental data and the authors' finite-element code are obtained from the public releases listed in `realdata/vhb/README.md`. From the ***realdata/vhb*** directory, first copy the author tree with `prepare_author_run.py`, then build the `platewithhole` variant with deal.II 9.6 inside the copied tree, and then run the calibration:
    ```bash
    python -I scripts/prepare_author_run.py \
        --source <path/to/davis-viscoelasticity-1.0.0> --dest runs/author_tree

    FIT3=runs/author_tree/fe_solver/input/fit3
    python -I scripts/setup_fit_tree.py --tree runs/author_tree --fit-dir "$FIT3"
    python -I scripts/setup_hybrid_interp.py --tree runs/author_tree \
        --fit-dir "$FIT3" --eq-scale 0.25
    python -I scripts/setup_extra_branch.py --fit-dir "$FIT3" \
        --nbranches 3 --mu 0.03 --c 0.292

    python -I scripts/fit_vhb.py --mode neq --model zener --tree runs/author_tree \
        --fit-dir "$FIT3" --iters 40 --jobs 3 --nbranches 3 \
        --init-zener 0.0374449422,0.071747,0.03,0.0249168939,1.1152242261,0.292 \
        --out results/fit_zener3
    cp -r "$FIT3/interp_neq" results/fit_zener3/interp_neq

    python -I scripts/fit_vhb.py --mode neq --model nn --tree runs/author_tree \
        --fit-dir "$FIT3" --iters 60 --jobs 3 --nbranches 3 --max-rel-step 5 \
        --nn-width 8 --nn-val-rate ldot3p75 --nn-val-every 1 --nn-patience 8 \
        --init-zener 0.005001,0.285059,0.051517,0.017075,5.16036,0.072203 \
        --out results/fit_nn3

    # the fits write their node values into the live tree; snapshot them
    cp -r "$FIT3/interp_neq" results/fit_nn3/interp_neq
    ```
    - Then evaluate both models on the five rates and collect the curves:
    ```bash
    RATES="ldot0p15 ldot1p5 ldot3p75 ldot7p5 ldot15p0"

    python -I scripts/fit_vhb.py --mode neq --model nn --tree runs/author_tree \
        --fit-dir "$FIT3" --iters 0 --jobs 5 --nbranches 3 \
        --experiments $RATES --init-nn results/fit_nn3/theta.npy \
        --out results/eval_nn3
    for r in $RATES; do
      python -I scripts/collect_eval.py --input runs/author_tree/calibration/input \
          --fit-dir "$FIT3" --rate "$r" --out "results/eval_nn3/curves_$r.npz"
    done

    python -I scripts/fit_vhb.py --mode neq --model zener --tree runs/author_tree \
        --fit-dir "$FIT3" --iters 0 --jobs 5 --nbranches 3 \
        --experiments $RATES \
        --init-zener 0.005001,0.285059,0.051517,0.017075,5.16036,0.072203 \
        --out results/eval_zener3
    for r in $RATES; do
      python -I scripts/collect_eval.py --input runs/author_tree/calibration/input \
          --fit-dir "$FIT3" --rate "$r" --out "results/eval_zener3/curves_$r.npz"
    done

    python -I scripts/per_rate_cost.py \
        --eval results/eval_nn3 results/eval_zener3 --out results/per_rate_cost.json
    ```
    - Finally, generate the comparison and function figures:
    ```bash
    python -I scripts/plot_comparison.py \
        --series "SemiPDE (NN):results/eval_nn3" \
        --series "Zener:results/eval_zener3" \
        --rates $RATES --out results/figures
    python -I scripts/plot_functions.py \
        --spline results/fit_nn3/interp_neq \
        --zener results/fit_zener3/interp_neq \
        --primary-label "SemiPDE (NN)" --out results/figures
    ```
    - Do not run two fits or evaluations concurrently on the same `runs/author_tree`: the solver input files are keyed by experiment name and are overwritten across runs.
